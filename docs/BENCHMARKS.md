# Бенчмарки NIKA Desktop

Мы разделяем скорость движка, качество модели и поведение приложения. Одна метрика
не подменяет другую. Результаты приведены для конкретных весов и оборудования.

## Локальная скорость

Замер: Qwen3.5 4B Q4_K_M, Apple M4 Pro, 24 ГиБ общей памяти, macOS 26.5.2.
Набор: llama-bench, Metal, 8 CPU-потоков, все доступные слои на GPU, Flash Attention
включён, KV-cache F16, batch 2048, microbatch 512. Прогрев включён; по 5 повторов.

- **pp512** — обработка синтетического промпта из 512 токенов.
- **tg128** — генерация 128 синтетических токенов с нулевой исходной глубиной.
- Значения — среднее и стандартное отклонение по повторам, токенов/с.
- Загрузка модели и SHA-256 не входят в замер скорости.
- Это отдельный benchmark-процесс, не полный путь SwiftUI → localhost → ответ.
  Он не измеряет TTFT, качество русского текста, выполнение задач или общий расход памяти.
- Это обычный рабочий Mac, без лабораторного контроля фоновой нагрузки и температуры.
- **M4 Pro с 24 ГиБ не подтверждает скорость и отсутствие swap на Mac с 8 ГБ.**

Сырые результаты и окружение: [M4 Pro / 4B Q4](benchmarks/m4-pro-24gb-qwen35-4b-q4/RESULTS.md),
[все повторы](benchmarks/m4-pro-24gb-qwen35-4b-q4/raw.json),
[оборудование и SHA-256](benchmarks/m4-pro-24gb-qwen35-4b-q4/environment.json).
Версия и commit llama.cpp находятся в каждой записи `raw.json`.

### Повторить на своём Mac

Установи `llama.cpp` и скачай Smart через приложение. Из корня репозитория:

```bash
python3 scripts/benchmark-local.py \
  "$HOME/Library/Application Support/NIKA Desktop/Models/Qwen3.5-4B-Q4_K_M.gguf" \
  --sha256 00fe7986ff5f6b463e62455821146049db6f9313603938a70800d1fb69ef11a4 \
  --output "build/benchmarks/my-mac-$(date +%Y%m%d-%H%M%S)"
```

Если приложение запущено через `scripts/dev.sh`, по умолчанию модель будет в
`.dev-data/Models/`. Измени путь аргумента; не запускай замер одновременно с чатом
или другой локальной моделью. Нужен существующий GGUF — скрипт ничего не скачивает.

Скрипт проверяет хеш, запускает 5 повторов, сохраняет `environment.json`, `raw.json`,
`engine.log` и `RESULTS.md`. Откажется перезаписывать существующий каталог. Для своего
GGUF можно опустить ожидаемый хеш: вычисленный SHA-256 всё равно попадёт в отчёт.
Логи движка остаются локально и не входят в репозиторий. Перед публикацией результатов
проверь локальные пути в `raw.json`.

[Методика llama-bench](https://github.com/ggml-org/llama.cpp/tree/master/tools/llama-bench).
[Точные веса](https://huggingface.co/unsloth/Qwen3.5-4B-GGUF/tree/e87f176479d0855a907a41277aca2f8ee7a09523).

## Качество модели

В README приведены три результата из [карточки Qwen3.5 4B](https://huggingface.co/Qwen/Qwen3.5-4B#benchmark-results),
проверенной 2026-10-13: MMLU-Pro 79,1; GPQA Diamond 76,2; IFEval 89,8.
Это оценки автора модели. Мы не воспроизводили эти наборы в NIKA и не приписываем
их Q4_K_M. Сравнение с облачными продуктами потребует одинаковой методики и настроек.

## Проверки приложения

Последний прогон XCTest: 44 теста, 39 пройдены, 5 пропущены, 0 ошибок (2026-10-13).
Пять пропусков требуют GGUF / vision-проектора / локального HTTP-стенда.
Это проверки корректности, не балл качества AI. Ранее реальные текстовые и визуальные
интеграционные проверки использовали Qwen3.5 0.8B; переменные для их запуска описаны в [руководстве по разработке](DEVELOPMENT.md#проверки).
